# 🪐 Gesture Space Explorer

[English](README.md) | **日本語**

Webカメラの前で手を動かして操作する、3D太陽系のWebアプリです。視点の回転、ズーム、惑星間の移動、指さしによる選択、時間の速さの変更をすべてハンドジェスチャーで行えます。手の認識は端末上で完結し（MediaPipe）、描画にはThree.jsを使用しています。

![v1.1の地球：4Kの地表、流れる雲、大気、昼夜の境界](docs/screenshots/after-earth.jpg)

## 主な機能

- **ハンドジェスチャー操作**：9種類のジェスチャーに対応しています（[操作方法](#操作方法)を参照）。互いに誤認識しないよう設計しています。操作できるのは画面に最も大きく映っている手だけなので、背景にいる人が割り込むことはありません。
- **プライバシー重視**：映像はブラウザの外に送信されず、保存もされません。MediaPipeのWASMとモデルを自前でホストしているため、**オフライン・キオスク環境**でも動作します。
- **キーボード／マウス操作にも対応**：カメラがなくてもすべての機能を使えます。
- **宇宙基地とロケットの旅（v2.0）**：実在の地点に5つの基地があります。ケープ発射センター（地球）、静かの基地（月）、ジェゼロ・ドーム（火星）、コナマラ氷基地（エウロパ）、クラーケン海岸（タイタン）。`V`（またはカードの **訪問**）で降りられます。行き先を選び（`←` `→`、天体を指さす、または一覧）、`Enter`・🚀ボタン・指で3→2→1のカウントダウンで発射。ロケットは弧を描いて飛び（`Enter`でスキップ）、最後は**自分で着陸**します。手のひら・マウス・矢印キーでパッドへ誘導し、重力の強い天体ほど難しくなります。**自動着陸**（着陸中に`Enter`、常にするなら`A`）もあります。燃料・実際の残り距離・到着までの時間・ミニマップを表示し、**パスポート**（`J`）には訪れた基地のスタンプが日付つきで端末に残ります。
- **リアルな惑星表現（v1.1）**
  - すべての天体に2Kテクスチャを使用し、**ズームした惑星だけ4Kに切り替えます**。デコードはメインスレッド外で行い、GPUへの転送も複数フレームに分散するため、読み込み中も手の認識が止まりません。
  - テクスチャの切り替えはすべてシェーダー内で**クロスフェード**し、急に表示が切り替わることはありません。
  - 大気のハロー（地球は青、火星はオレンジ、金星は黄色）、地球の流れる雲、夜側の都市の灯り、海面の太陽の照り返しを表現しています。
  - 土星の環には本体の影が落ち、太陽には周縁減光とブルームをかけています。全体にACESトーンマッピングを適用しています。
- **見やすいスケール**：惑星の大きさは直径の0.38乗で圧縮し、軌道間隔は対数スケールにしています。大小の順序を保ったまま、全体表示でもすべての惑星がはっきり見えます。衛星は惑星のまわりで、より詰めた独自の間隔で並べています。ズームアウトすると惑星を最大1.8倍に拡大し（隣の惑星や土星の環が近い場合は控えめに）、衛星はフェードアウトするので、全体表示でも見やすくなります。近くでは実際の比率どおりです。**実際の大きさ**（`T` またはフッターのボタン、端末に保存）でこの拡大をオフにできます。
- **滑らかなカメラ**：惑星を切り替えると、1.5秒のイージング付きで近接軌道の視点まで飛んでいきます。`prefers-reduced-motion` が有効な場合は即座に切り替えます。
- **画質設定**：フッターでLow／Highを切り替えられます。スマートフォンとタブレットでは自動的にLowになります。切り替えはリロードやカクつきなしで即時に反映されます。
- **フォトモード**：🤘（または `P`、📷ボタン）でUIを隠してシャッターを切り、シーンをPNGで保存します。「アプリ名＋惑星名」の透かしは `W` で切り替えられます。スマートフォンでは、共有ボタンからシステムの共有シートを開けます。
- **実際の位置を、好きな日付で（v1.2）**：惑星は表示中の日付で実際にある位置に並び（JPLの軌道要素）、実際の自転軸で自転します（IAUのデータ）。そのため地球の季節や昼側の向きもカレンダーどおりです。タイムバーに日付を表示し、時間の速さを「1年/秒で逆行」から停止・実時間を経て「1年/秒で順行」まで変えられます。**今** で今日に戻ります。🤙 で手を傾けるとタイムダイヤルを回せます。
- **衛星（v1.3）**：地球の月、木星のイオ・エウロパ・ガニメデ・カリスト、土星のタイタンが、表示中の日付の実際の位置にあり、いつも同じ面を惑星に向けています。惑星にフォーカスしてから `M` を押すか、衛星を指さす・クリックする（または解説カードのボタンを使う）と、その衛星まで飛んでいきます。
- **本物の星空**：背景の天の川は、ESAのガイア計画のデータをもとにしたNASAの星図です。天の川の帯や明るい星が実際の空と同じ位置に来るよう向きを合わせています（シリウス、ベガ、銀河中心の位置はテストで確認しています）。ときどき流れ星が横切ります（`prefers-reduced-motion` が有効なときは表示しません）。
- **冥王星とハレー彗星**：「準惑星」と表示される冥王星と、ハレー彗星が、実際の傾いた楕円軌道を進みます（冥王星は1979〜1999年、実際に海王星の軌道の内側にありました）。彗星は約4 AUより内側でコマと2本の尾を伸ばします。太陽のちょうど反対側を向くまっすぐな青いイオンの尾と、曲がったダストの尾です。ハレー彗星は今は遠くにあるので、解説カードの **次の回帰** ボタンで、2061年7月へ1日/秒の速さで移動できます。全体表示は海王星の軌道に合わせています。冥王星やハレー彗星の軌道はズームアウトすると見えます。
- **小惑星帯とカイパーベルト**：火星と木星のあいだに数千個の岩石（Highで6,000個、Lowで1,500個）。木星の引力で空いたカークウッドの空隙も再現し、それぞれがケプラーの法則どおりの周期で回るので、内側の岩石が外側を追い越していきます。海王星のすぐ外側には、うっすらとカイパーベルトがあります。
- **ほかの星でのあなたの体重**：体重を入力すると（⚖️ または `G`）、水星から太陽まで、それぞれの天体で体重計が示す値を表示します（NASAの表面重力）。惑星の解説カードには、その星でのあなたの体重と、表示中の日付で太陽の光が届くまでの時間も表示します。
- **ジェゼロ基地をショーケースに（v2.1）**：火星の基地が小さな拠点になりました。トンネルでつながった3つの膨張式居住棟、光る温室、太陽を追う太陽電池パネル、探査車のガレージ、通信アンテナ。2台の探査車が巡回し、宇宙飛行士がモジュールの間を歩きます。地面は惑星の曲面に沿い、端は惑星の表面に溶け込みます。一日も本物で、地方太陽時・日の出・日の入りを暦から計算し、夕暮れには窓に明かりがともります。**地平線ビュー**（`O` または 🌄）では地面に立てます。昼はバタースコッチ色の空、火星らしい青い夕焼け、夜は本物の星空に、満ち欠けするフォボス、ダイモス、明るい星としての地球が実際の位置に見えます。火星にフォーカスしている間だけ作られ、離れると解放されます。
- **見ごたえのあるロケット（v2.2）**：コードで作り、塗装まで生成する2段式ロケットとクルーカプセル。途中でブースターを切り離し（カメラが振り返って落ちていくブースターを映します）、上段は自分の脚で着陸します。炎の色は大気によって変わり、エンジンはパッドの砂を巻き上げます（火星は赤い砂、月では舞いません）。
- **本物の光のジェゼロ（v2.3）**：High・Ultraでは基地に実際の空からの太陽があり、影、空の映り込み、コードで生成した素材（布、波板、太陽電池、風上側の砂汚れ）で描きます。基地カードの **🌅 ゴールデンアワー** で次の日没前に移動し、地平線ビューで長い影を見られます。
- **AstroLife 2126（v2.6、試験機能：`?flags=astrolife`）**：エクスプローラーを中心にした架空の宇宙旅行アプリです。4つの行き先を読み、ケープ→ジェゼロを予約し（ニックネーム、出発便、客室）、チェックインするとQRコード付きの搭乗券がもらえます（QRはお土産リンク）。そして実際に飛びます：エクスプローラーが宇宙港で開き、日付は次の実在の地球–火星打ち上げウィンドウ（2127年3月）による出発日に移ります。ジェゼロに着陸すると、パスポートに旅のスタンプが押され、保存・共有できるポストカードが作れます。運賃・定期船・9日間の航行は架空で、画面にもそう表示されます。データはすべて端末内に残り、サーバーはありません。お土産リンクは搭乗券を`#`の後ろに載せるため、ブラウザがサーバーに送ることはありません。カメラはエクスプローラーを開くまで使いません。フラグがなければ、何もダウンロードされません。
- **多言語対応**：アプリのUIと惑星の解説は**英語・ビルマ語・日本語**に対応しています（`L`キーで順に切り替え）。このREADMEは英語版と日本語版があります。
- **テスト**：Vitestによる236件のテストがあります。実際のMediaPipeの記録データを再生するジェスチャー認識のテスト、実際の天文現象（春分・秋分、衝、近日点）と照合した惑星の位置、JPL Horizonsと照合した衛星・冥王星・ハレー彗星の位置、星図上の明るい星の位置、カメラの移動と構図、スケールの不変条件、惑星が要求しうるテクスチャファイルがすべて同梱されているかの確認を含みます。

## 操作方法

| ジェスチャー | 動作 |
|---|---|
| ✋ 手のひらを開いて動かす | 視点を回転 |
| ✌️ Vサインを約0.5秒キープ | 次の惑星へ |
| ✌️ Vサインのまま左右にスワイプ | 前／次の惑星へ（1回のVで1回だけ切り替え） |
| 🤏 つまんだまま上下に動かす | ズームイン／アウト |
| ☝️ 惑星を指さして約1秒キープ | 惑星を選択して解説を表示（表示中の惑星の衛星も選べます） |
| ✊ こぶしを約0.5秒キープ | 時間の一時停止／再開 |
| 🤏🤏 両手でつまんで広げる／狭める | 時間を速く／遅く |
| 🤘 人差し指と小指を立てて約0.8秒キープ | 写真を撮る |
| 🤙 親指と小指を伸ばして静止し、左右に傾ける | タイムダイヤル：右に傾けると速く進み、左に傾けると遅く、さらに逆行（どちらの手でも可） |

ジェスチャーはすべて**異なる手の形**で区別しており、動きの速さだけで意味を判定することはありません。

- ✋ 開いた手のひらは、どれだけ速く動かしても回転だけを行い、惑星は切り替わりません。
- ✌️ Vサインでは回転しません。スワイプとして受け付けるには、方向・最小移動距離（手のひらの大きさとの比）・速さの3条件を満たす必要があり、その後にクールダウンがあります。
- ☝️ 指さしと ✌️ Vサインは、中指が伸びているかどうかで区別します。
- 🤙 タイムダイヤルは、手の形を約0.3秒静止させてから動き始めるので、形を作る途中で速さが変わることはありません。ダイヤルの操作中とその後0.5秒間は 🤘 で写真を撮れないため、親指を一瞬見失った 🤙 が 🤘 と誤認されることはありません。傾きは左右どちらの手でも「右＝速く」になるように測っています。

**キーボード／マウス：** `←` `→` 惑星の切り替え（その後に冥王星、ハレー彗星） · `↑` `↓`／ホイール ズーム · ドラッグ 回転 · `Enter` 選択 · `Esc` 閉じる · `Space` 一時停止 · `[` `]` 時間の速さ · `B` 時間の逆行 · `N` 現在に戻る · `M` フォーカス中の惑星の衛星を順に表示 · 惑星や衛星をクリックしてそこへ移動 · `P` 写真 · `W` 透かしのオン／オフ · `T` 実際の大きさ（全体表示での拡大をオフ） · `G` 体重パネル · `V` 基地を訪問（基地では `←` `→` で行き先、`Enter` で発射。着陸中は矢印で誘導、`Enter` で自動着陸） · `O` ジェゼロの地平線ビュー（ドラッグで見回す） · `A` 常に自動着陸 · `J` パスポート · `L` 言語（英語 → ビルマ語 → 日本語） · `D` デバッグ表示 · `F` FPSカウンター（開発ビルド、または `?debug` 付きのとき）。マウスやタッチでは、タイムバーの速さスライダー（中央＝停止）、**今** ボタン、一時停止ボタンを使えます。

## クイックスタート

必要なもの：Node.js **20.19以上**（または22 LTS）、Webカメラ

```bash
git clone <repo-url> hand-gesture
cd hand-gesture
npm ci            # postinstallでMediaPipeのWASMとモデルをpublic/にコピーします
npm run dev       # http://localhost:5173
```

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm run build` | 本番ビルド（`dist/`） |
| `npm run preview` | ビルドをローカルで確認 |
| `npm test` | Vitest |
| `npm run typecheck` | TypeScriptの型チェック |
| `npm run textures:build` | 元画像から `public/textures/` を作り直す（[テクスチャ](#テクスチャ)を参照） |

**デバッグモード：** `?debug=1` または `D` キーで、描画と検出のFPS、検出時間、トラッカーの状態、認識中のジェスチャー、ランドマークのオーバーレイ、設定パネル（lil-gui）を表示します。設定パネルでは、しきい値、露出、ブルームをその場で調整できます。デバッグモードで `R` を押すと**ランドマークの記録**を開始・停止し、JSONとしてダウンロードします。これを `tests/fixtures/` に置くと、再生テストとして使えます。

## 画質設定

| | Low | High |
|---|---|---|
| テクスチャ | 1K（近接時2K） | 2K（近接時4K） |
| ブルーム | なし | あり |
| ピクセル比 | 1 | 最大2 |
| デフォルト | スマートフォン・タブレット | デスクトップ |

**Ultra**（v2.2、デスクトップのみ。画質ボタンで選択）：4Kディスプレイ向けにピクセル比を最大3、8× MSAA、生成テクスチャも高精細に。処理が追いつかない場合は自動でHighに戻ります。

選んだ画質は保存され、切り替えはリロードなしで即座に反映されます。

## パフォーマンス

**計測環境：** Windows 11のノートPC（RTX 4060 Laptop GPU、Chrome、ANGLE/D3D11）。合成カメラ映像を使い、GPU上で手の認識を動かした状態で計測しました。

| | 結果 |
|---|---|
| フレームレート（High、1600×900と3200×1800） | 144Hzディスプレイで**144fps**を維持。p99フレーム時間は7.1ms |
| 1フレームあたりのGPU時間（High） | 中央値**3.8〜4.8ms**、p95で6.2ms以下（60fpsの1フレームは16.7ms） |
| 1フレームあたりのGPU時間（Low） | 中央値**0.5〜1.0ms** |
| 4Kテクスチャ読み込み中の最悪フレーム | **69ms → 14ms** |
| 初回のLow → High切り替え時の最悪フレーム | **33〜150ms → 17〜18ms**（本番ビルド、iPhoneエミュレーション、60Hzディスプレイ） |

GPU時間は、各フレームをWebGLのタイマークエリ（`EXT_disjoint_timer_query_webgl2`）で囲んで計測しています。

#### v2.3の負荷（基地の太陽、影、素材）

| ビュー（CPU / GPU, ms） | v2.2 High | v2.3 High | v2.2 Low | v2.3 Low |
|---|---|---|---|---|
| 基地ビュー | 2.5–2.6 / 2.5–2.6 | 4.0–4.5 / 3.3–3.5 | 2.5–2.7 / 1.0–1.5 | 2.6–2.7 / 0.9–1.8 |
| 地平線ビュー | 2.4–2.5 / 2.5–2.7 | 3.1–4.1 / 2.8–3.4 | 2.2–2.6 / 0.5–0.7 | 2.2–2.3 / 0.6–1.4 |
| 着陸 | 2.9–3.0 / 2.7–2.9 | 4.1–4.3 / 3.7–4.1 | 2.4–2.6 / 1.3–1.4 | 2.6–3.5 / 0.7–2.1 |

Highでは基地でGPUが0.7–1.2 ms、CPUが約1.5 ms増えます。Lowは変わりません（2つ目の描画パスなし）。影と映り込みは、太陽・ロケット・配置が変わったときだけ描き直します。

#### v2.1の負荷（ジェゼロのショーケース）

昼のジェゼロの基地ビュー、1600×900、RTX 4060 ノートPC、ヘッドレス Chrome。各バージョンを単独で計測（`?debug` の読み値3回の中央値）：

| ビュー | v2.0.2 CPU / GPU | v2.1 CPU / GPU |
|---|---|---|
| 基地ビュー、High | 2.1–2.2 / 4.1–4.2 ms | 2.0 / 1.8–2.2 ms |
| 基地ビュー、Low | 1.8–1.9 / 2.5–3.4 ms | 1.8–1.9 / 0.9–1.6 ms |
| 地平線ビュー、High（新規） | — | 2.3 / 3.9–4.2 ms |
| 地平線ビュー、Low（新規） | — | 1.9 / 0.6–1.0 ms |

v2.1 の GPU 時間が*短い*のは、ショーケースの負荷がゼロだからではありません。v2.1 では基地ビューの画角が近く、描画負荷の高い火星の表面が画面に占める割合が小さいためです。ショーケース自体の追加は High で 15 メッシュ・4.8k 三角形（Low で 14・3.0k）、地平線の空が 5 ドローコール、アニメーションの CPU は1フレームあたり約 0.01 ms です。火星にフォーカスしていない間は一切存在しません。

#### v1.3の負荷（衛星、小惑星帯、冥王星、彗星、星空）

同じノートPCで、v1.2とv1.3の本番ビルドを並べ、`?debug` のCPU/GPU表示から読み取りました。1秒間の1フレームあたり平均GPU時間を6回読み、その中央値を取って、それぞれ2回ずつ計測しています。キーボード操作（手の認識なし）なので、上の表より低い値です。表示サイズは1600×900、デバイスピクセル比2で、Highは3200×1800、Lowは1600×900で描画しています。

| 表示 | High（前 → 後） | Low（前 → 後） |
|---|---|---|
| 全体表示 | 2.8 → 3.5ms | 1.3 → 1.2ms |
| 地球に接近（Highは4K、Lowは2K） | 3.5 → 3.9ms | 1.6 → 1.9ms |
| 木星（衛星つき） | 2.7 → 3.2ms | 0.9 → 1.3ms |
| 土星（タイタンつき） | 2.6 → 3.1ms | 1.2 → 1.0ms |
| カイパーベルトと冥王星までズームアウト | — → 3.3ms | |
| 小惑星帯の中 | — → 3.0ms | |
| 近日点のハレー彗星の尾 | — → 3.9ms | — → 2.1ms |

- **High：1フレームあたり+0.4〜0.7ms。** 星空・小惑星帯・衛星を合わせた増加分です（個別には計測していません）。それでも60fpsの1フレームの4分の1以下で描き終わります。
- **Low：計測できるほどの変化はありません。** 約1msの負荷では、実行ごとに±0.4msほどぶれ、差よりも大きくなります。
- **1フレームあたりのCPU時間：** 前は1.2〜1.5ms、後は1.4〜1.8msです。岩石は頂点シェーダーで動かすのでCPU時間はかからず、増えた分は衛星・彗星・星空の処理です。
- **メモリ：** 星空はHighで32MB、Lowで8MBです。衛星のテクスチャは、その惑星を訪れたときに初めて読み込みます。

### 高速化の工夫

- **4Kは見えるところだけ。** すべての惑星は2K（Lowでは1K）で読み込みます。4K（Lowでは2K）に切り替えるのは選択中の惑星だけで、しかも基本テクスチャでは足りない大きさで表示されたときだけです。2Kテクスチャは見えている円盤の幅におよそ650テクセルしかないため、約650デバイスピクセルで切り替えます。ヒステリシスと短い待ち時間を設けているので、素早くズームしただけではダウンロードは始まりません。ズームアウトするか別の惑星に移ると、4Kテクスチャは `dispose()` で解放します。4Kテクスチャ1枚はGPUメモリを約45MB使うため、それ以外の場面ではこのコストが一切かかりません。
- **読み込み中もフレームが止まらない（69ms → 14ms）。** 画像は `createImageBitmap` でメインスレッド外でデコードし、32MBを一度に転送する代わりに約2MBずつ1フレームに1回GPUへ転送します。また、デコード時の上下反転（`imageOrientation: 'flipY'`）がChromeでフレーム落ちの原因になっていたため、画像は上の行から順に保持し、代わりに球体のUVを反転しています。手の認識も同じスレッドで動いているため、長いフレームはそのままジェスチャーの遅れになります。
- **シェーダーを再コンパイルしないクロスフェード。** マテリアルのテクスチャスロットには最初から（1×1のプレースホルダーを含め）必ずテクスチャが入っています。シェーダーは各スロットとその「次」のテクスチャを混ぜる（`mix(map, mapNext, fade)`）ので、テクスチャを入れ替えてもシェーダーは変わりません。
- **土星の環の影はシェーダーで計算。** フラグメントシェーダーが、環の各点から太陽へ向かうレイが惑星の球に当たるかを判定します。点光源である太陽にシャドウマップを使うと、毎フレーム6回の追加描画が必要になります。
- **見分けがつかないところではポリゴンを減らす。** 選択中の惑星と画面上で大きく見える惑星は128分割、遠くの惑星は64分割または32分割の球を使います。
- **ブルームはHighのみ。** ブルーム用のバッファはオンのときだけ確保するため、スマートフォンの既定であるLowではメモリを使いません。
- **画質切り替えでカクつかない。** 起動後、ブラウザがアイドルのあいだに、もう一方の画質で使うシェーダー（ブルーム自体のものを含む）をバックグラウンドでコンパイルしておきます（`renderer.compileAsync`）。本番ビルドでは、Three.jsのシェーダーエラーチェックも無効にしています。このチェックは、各シェーダーの初回使用時にGPUとの同期的なやり取りが発生するためです。

### 手元の端末で計測する

URLに `?debug` を付けて開くと（例：`https://<アプリのURL>/?debug`）、右上にFPSカウンターが表示されます。タップすると、FPS、1フレームあたりのミリ秒、メモリの表示が切り替わります。その下の **CPU** と **GPU** は、1フレームにかかる時間を直近1秒の平均と95パーセンタイルで示します。CPUはアプリ自体の1フレームの処理（シーンの更新、描画命令、HUD）、GPUはグラフィックスカードが描画にかける時間です。GPU時間の計測にはWebGLのタイマークエリが必要で、デスクトップ版のChromeとEdgeは対応しています。対応していない環境（Safari、Firefox、多くのスマートフォン）では *n/a* と表示されますが、CPU時間で端末どうしを比較できます。フッターの画質ボタンでLowとHighを比較できます。`?debug` では、[クイックスタート](#クイックスタート)で説明しているデバッグ表示も有効になります。

### 既知の制限

- **古いSafari（17未満）とFirefox（98未満）** は、ここで使っている画像デコードのオプションに対応していないため、テクスチャをメインスレッドでデコードします。そのため読み込み時、特に4Kへの切り替え時にカクつくことがあります。現行バージョンには影響しません。
- **スマートフォン：** Low画質は中程度の性能のスマートフォン向けに設計していますが、**実機ではまだ計測していません**。そのための `?debug` です。
- **ハレー彗星の位置が正確なのは、1986年と2061年の回帰の前後だけです。** ここでの軌道は、その2回の近日点を通るように合わせた二体問題の楕円です。実際の軌道は木星や土星の影響で回ごとに違う伸び方をするため、それ以外の回帰は数か月ずれます。1910年の回帰は約4か月遅れ、2061年の次の回帰は2137年1月と表示されます（実際は2134年3月）。
- **冥王星の南半球は単色で表示します。** 2015年のニューホライズンズは南半球を撮影できなかった（夜側だった）ため、撮影できた最も近い緯度の平均色で埋めています。
- **基地（v2.0）はデフォルメしています。** 基地やロケットは実際よりずっと大きく描き、旅は数秒で、実際の遷移軌道ではなく見やすい弧を飛びます。燃料はゲーム上の数値です。HUDの距離は実際の値（暦計算）です。
- **基地にいる間は時間が実時間で進みます。** 基地が回り去らないようにするためで、離れると元の速さに戻ります。
- **スマートフォンでは基地パネル**が情報シートのようにカメラをずらさないため、小さな画面では基地の一部を覆うことがあります。
- **フォボスとダイモスはジェゼロの空（地平線ビュー）にだけ表示します。** 訪問できる天体ではなく、火星で `M` を押すと訪ねられる衛星はないと表示されます。位置は 2020–2035 年の JPL Horizons に合わせてあり（誤差 3.2° と 1.9° 以内）、その範囲外ではフォボスを「概略」と表示します。空では実際の6倍の大きさで描きます（実際の大きさ表示がオンのときは実寸）。
- **地平線ビューはデフォルメです。** このアプリの縮尺では火星の半径が基地数個分しかないため、惑星の曲面の代わりに平らな地面と空のドームを使っています。
- **ショーケースはジェゼロだけです。** 他の4基地は v2.0 の建物のままです（再利用できるキットとして作っています）。

## 仕組み

```
src/
  main.ts             各部の接続と描画ループ
  intents.ts          Intent型とバス：すべての入力をIntentに変換
  config.ts           調整可能な数値の一覧（デバッグモードでその場で編集可能）
  quality.ts          Low／Highのプロファイル、モバイル判定
  data/               bodies.ts（惑星データ：軌道、自転軸、英語／ビルマ語／日本語の解説）、
                      ephemeris.ts（日付から位置と自転軸を計算）、scale.ts（大きさと距離の圧縮）、weight.ts
  sim/clock.ts        シミュレーション上の日付と時間の速さ
  input/keyboard.ts   キーボード＋マウス → Intent
  gestures/           perception（ランドマーク → 手の形）+ engine（→ Intent）。Three.jsに依存しない純粋なロジック
  tracking/           カメラ、MediaPipeのハンドトラッカー、One Euroフィルター
  scene/              solarSystem、cameraRig（移動と構図）、picking、postprocessing（ブルーム）
  planets/            天体の構築：マテリアル、大気、環、太陽、
                      surface（テクスチャの解像度切り替えとクロスフェード）、textureLoader、プログラム生成のフォールバック
  ui/                 HUD、ジェスチャーHUD、ラベル、デバッグ表示、レコーダー、i18n
scripts/              copy-mediapipe-assets.mjs、build-textures.mjs
public/textures/      1K／2K／4Kの惑星テクスチャ（合計約11MB）
tests/                Vitest
```

- **入力はシーンを直接操作しません。** キーボード・マウス・ジェスチャーはすべて `Intent` を発行し、シーンはそれにだけ反応します。そのため、ジェスチャーのコードはブラウザなしでテストできる純粋なTypeScriptになっています。
- **テクスチャ**は最初のフレームの後から読み込み、届くまでは各天体を基本色で表示します。画像を読み込めない場合は、従来のプログラム生成テクスチャで表示します。読み込みでフレームを止めない仕組みは[パフォーマンス](#パフォーマンス)で説明しています。
- **エフェクト**は、Three.js標準の物理ベースマテリアルへの小さなパッチ（`onBeforeCompile`）と、大気のハロー用の独自シェーダー1つで実装しています。
- **時間：** 各惑星の日心黄経は、JPLのケプラー要素を表示中の日付について解いて求めています。距離は見やすい対数スケールのままなので、実際どおりなのは方向だけです。自転軸と本初子午線はIAUの自転モデルによります。高速で進めているときは、ちらつかないよう表示上の自転を毎秒36°までに抑え、時間がゆっくりになると正確な角度に追いつきます。
- **スケール：** 半径は直径の0.38乗に比例します（地球＝2単位）。惑星の間隔はln(AU単位の距離)に従い、並んだときにも隣どうしが（環や衛星も含めて）重ならないよう最小間隔を設けています。この最小間隔のため、地球と火星は（月のぶん）少し外側に、土星・天王星・海王星は（木星の衛星、土星の環、タイタンのぶん）さらに外側に移っています。全体表示の構図は実際のカメラの投影に対して数値的に求め、すべての惑星の軌道が画面に収まるようにしています。
- **星空：** カメラを囲む球を奥行きなしで最初に描き、シェーダーで各ピクセルの方向を赤経・赤緯に変換して星図を参照します。`scene.background` を使うと4Kの星図が約130 MBのキューブマップに変換されるため、この方式にしました。星図そのものはHighで32 MB（4K）、Lowで8 MB（2K）で、元の大きさより小さく表示されることはないのでミップマップも持ちません。常に画面に映っている唯一のテクスチャなので、「4Kは近くで見るときだけ」の唯一の例外です。星図はNASAのHDR（OpenEXR）ファイルから、`npm run textures:build` の中でthree.jsのEXRデコーダーを使って作っています。
- **冥王星と彗星**は、3次元の実際の位置に、実際の距離を惑星の対数スケールで換算して置いています（`sceneDistance`。どの惑星の軌道もちょうど通ります）。冥王星は惑星と同じくJPLの軌道要素を使います（Horizonsとの差は0.05°以内）。ハレー彗星の軌道は、JPL Small-Body Databaseの二体問題の楕円で、周期を1986年と2061年の近日点に合わせています（その間はHorizonsとの差が約3°以内）。それ以外の回帰は数か月ずれます。尾は毎フレーム作り直すカメラ向きの帯で、加算合成で描いています。
- **小惑星帯：** 帯ごとに1つの `InstancedMesh`（描画呼び出し1回）です。インスタンス行列には岩石ごとの大きさと向きだけを持たせ、軌道上の位置は日付から頂点シェーダーで計算します。そのため数千個の岩石を動かしてもCPU時間はかからず、Lowでは描く数を減らすだけで済みます。岩石は実際の軌道長半径を持ち、火星と木星の衛星系のあいだの空いた帯に、対数スケールで並べています。
- **衛星：** 大きさは惑星の規則の半分で、衛星どうしの大小関係を保ち（最大はガニメデ）、どの惑星よりも小さく表示します。距離は別に圧縮しています。いちばん内側の衛星は惑星の環や大気のすぐ外に置き、残りは最小間隔を保ちながら対数スケールで並べるので、カリストはちゃんと一番外側にあります。位置はJPL Horizonsに合わせた平均黄経から求めています（1950〜2100年で、ガリレオ衛星は約1°以内、タイタンは0.1°以内）。月はミーウスの月の理論の主要項を使うので、満ち欠けや食の日付も合います。高速時は衛星系全体をまとめて遅くするので4：2：1のリズムが保たれ、どの衛星もいつも同じ面を惑星に向けています。

## デプロイ（Vercel）

静的なViteアプリのため、サーバー側のコードも環境変数も不要です。

| 設定 | 値 |
|---|---|
| Framework Preset | **Vite** |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js Version | **22.x** |

- **アセット：** Vercelのインストールキャッシュで `postinstall` が飛ばされても、`prebuild` でMediaPipeのWASMをコピーします。コピー用のスクリプトは、ファイルが見つからない場合やモデルのSHA-256が一致しない場合にエラーで終了するため、不完全なビルドが黙ってデプロイされることはありません。
- **バージョン管理：** WASMは**バージョン付きのパス**（`/mediapipe/<version>/wasm/`）に置くので、`immutable` でキャッシュできます。ハンドモデルはnpmパッケージに含まれないため `assets/models/` にコミットしており、インストールとビルドにネットワークは不要です。
- **CI：** GitHub Actions（[`.github/workflows/ci.yml`](.github/workflows/ci.yml)）が、PRごとに型チェック・テスト・ビルドを実行します。

`vercel.json` では次を設定しています。COOP／COEPヘッダーは不要です（`SharedArrayBuffer` を使っていないため）。iframeに埋め込む場合は `<iframe allow="camera">` が必要です。

- `Permissions-Policy: camera=(self)`
- バージョン付きのMediaPipeとモデルのファイルに `immutable` キャッシュ
- ファイル名にバージョンを含まない `/textures/` に、1日のキャッシュとstale-while-revalidate

プルリクエストごとにVercelの**プレビューURL**が発行され、`main` にマージすると本番環境にデプロイされます（CLIの場合は `npx vercel`、`npx vercel --prod`）。

**デプロイ後の確認項目：**

- [ ] `.wasm` が `application/wasm`、ステータス200で配信されている
- [ ] `/models/*.task` が404にならない
- [ ] `/textures/2k/earth_day.jpg` が読み込める
- [ ] レスポンスヘッダーに `Permissions-Policy` が含まれている
- [ ] カメラを拒否するとキーボード操作に切り替わる
- [ ] シークレットウィンドウ（キャッシュなし）で読み込み時間を計測する

### 展示・キオスク（オフライン）

```bash
npm run build && npm run preview
```

インターネット接続は不要です。Chromeを `--kiosk` モードで起動し、**同じマシン上で** `http://localhost:4173` を開いてください。`--host` を付けてLANのIPアドレスから開くとセキュアコンテキストにならず、カメラが使えません。カメラの許可をあらかじめ与えるには、エンタープライズポリシーの `VideoCaptureAllowedUrls` を使います。手早く設定するなら `--use-fake-ui-for-media-stream` フラグも使えます。

## プライバシー

- カメラの映像はブラウザ内で処理され、サーバーには送信されません。
- 映像・画像・ランドマークのデータは保存しません。
- AstroLifeの予約・搭乗券・スタンプ（`?flags=astrolife`）もこのブラウザ内だけに保存され、パスポート画面からすべて削除できます。搭乗券のお土産リンクは、ニックネーム・アバター・便・客室を`#`の後ろに載せるため、共有した相手には届きますが、サーバーには届きません。
- デバッグ用のレコーダーは、利用者が自分で開始した場合にだけ、ランドマークの数値（画像ではありません）を手元にダウンロードします。
